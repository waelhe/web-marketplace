## 0. لماذا هذا البروتوكول

بيئة التنفيذ تنهار بصمت بين الجلسات: الاستنساخات والأدوات والأسرار
المحلية وسجل العمل — كلها ضاعت مرتين (2026-09-27/28، مقيساً). ما نجا
كل مرة: **GitHub**. لذلك كل شيء هنا مبني على قاعدة واحدة:

> **GitHub هو الحقيقة الوحيدة. لا يُصدَّق أي حالة محلية قبل إعادة
> اشتقاقها من GitHub. لا يُخزَّن أي ثمين إلا على GitHub.**

والذاكرة الدائمة للمنتج ليست ذاكرة الوكيل بل **وثائق المستودع**: سجل
الرحلات في الميثاق (§4/§6)، وخريطة العقد، وسجل الـ PRs.

وأنت مهندس برمجيات محترف — Next.js وReact وTypeScript وOAuth2 و
Better Auth — تعمل بتوصياتها الرسمية استناداً إلى **الوثائق الرسمية
المحزومة المطابقة للإصدار** وتجارب المجتمع المعتمدة، لا إلى بيانات
تدريبك: **هذه ليست الـ Next.js التي تعرفها**، و16.3.5 يكسر ما تعرفه.
التسلسل المعرفي الملزم: (1) الوثائق الرسمية المحزومة
`node_modules/next/dist/docs` + ملف `AGENTS.md` (بلوكه المُدار لا
يُلمس) + وثائق Better Auth وReact بالإصدار المثبت؛ (2) ما غاب عن
المحزوم فمصدره الشبكة **بنفس الإصدار فقط** (`nextjs.org/docs/....md`
أو `llms.txt`) لا من الذاكرة؛ (3) عند تعارض النص مع التطبيق العامل
**التطبيق يحكم** — حقائق `/_next/mcp` و`agent-browser` هي الكلمة
الأخيرة. كلمة المالك الدائمة: «لا أريد ما تراه أنت صحيحاً، أريد
التصميم الرسمي حسب الإطار والنظام وحقائق الكود». وتعمل على **نظام
BFF كامل** (مصادقة + بروكسي + جلسة) لا أجزاء: كل تعديل يُحافظ على
النظام كله، ولا ترقيع يترك ديناً.

## 2. طقس إقلاع الجلسة (بالترتيب، كل جلسة)

1. **جرد الناجي**: `ls /home/z/my-project/` — الاستنساخات موجودة؟
   `git log` يطابق GitHub؟ `.creds/gh_token` حي؟
2. **إعادة مزامنة** (ff-only أبداً لا دمج أعمى): `git fetch origin &&
   git checkout main && git merge --ff-only origin/main` للواجهة؛
   `git fetch origin` للباك اند. استنساخ مفقود → إعادة استنساخ بالتوكن.
3. **قراءة الحالة الدائمة من الشجرة**: الميثاق (سجل الرحلات = ما
   التالي؛ سجل مدخلات المالك = ما ليس لنا)، الخريطة (خريطة العقد)،
   `git log --oneline -10`.
4. **PRs المفتوحة على المستودعين معاً** عبر API — عمل واجهة سابق قد
   ينتظر الدمج؛ وPRs الباك اند المفتوحة **خطر عقدٍ قادم** (موجة مدمجة
   تغيّر الـ OpenAPI الذي نستهلكه — درس #403: عقد مرقّم كسر الصندوق).
   تُقرأ عناوينها، ويُعاد قياس OpenAPI إن تقدّم main.
5. **ذيل worklog** إن نجا (`/home/z/my-project/worklog.md` — ذاكرة أفضل
   جهد، وقد **تتأخر عن GitHub** بـ PR غير مسجّل؛ عند أي تعارض GitHub هو
   الحاكم: إعادة اشتقاق من `git log` + قائمة PRs، لا تخمين).
6. **قراءة AGENTS وتسليح الحلقة الحية** (قبل أي تعديل): ملف `AGENTS.md`
   في جذر المستودع — البلوك المُدار أعلاه يكتبه `next dev` (التحقق:
   `node_modules/next/dist/server/lib/generate-agent-files.js`) **لا
   يُلمس** (حذفه لا يزيله بل يعيد إنشاء تغيير غير ملتزم؛ إن أعادت
   `next dev` كتابته رافق الالتزام) والقواعد الخاصة تحته تقيّد كل
   تعديل. ثم قراءة `.agents/skills/next-dev-loop/SKILL.md` (متتبَّعة
   في git — دائمة) — **تُتَّبع حرفياً بدءاً من الـ preflight**. وقبل
   أي خادم تطوير: قراءة `.next/dev/lock` (يكتب فيه `next dev` الـ pid
   والمنفذ والعنوان — دليل `ai-agents` المحزوم): قفل حي ← **اتصل
   بالخادم القائم ولا تبدأ مكرراً**؛ قفل ميت والخادم لازم ← ابدأه أنت.
7. **إعادة بناء العدة إن فُقدت**: `npm_config_engine_strict=false npm ci`
   (نظام Node 24 يعمل رغم pin 26.8.2 — البديل المقيس الموثّق)، وبناء
   `.env.local` على staging.
8. **قياس قبل البناء**: OpenAPI حي + probing لأطراف الشريحة على staging
   (شكل النجاح + كل أشكال الفشل). إنتاج الباك اند قد يمر بنوافذ 502/000
   عابرة — إشارة تُبلَّغ لا عقدٌ يتغير. وكل ادّعاء تطابق بيئتين يحمل
   **تاريخ قياسه** (يصح فقط كما قيس، وقد يتعذّر تحقّقه أثناء نافذة عطل).

## 3. القواعد الخمس (توجيه المالك 2026-09-28)

1. **التعريف قبل البناء** — العمل يبدأ من رحلة ومواصفة قبول في الميثاق،
   لا من endpoint موجود. عملٌ لا يخدم رحلةً مسجّلة لا يُنفَّذ.
2. **شرائح رأسية** — كل دورة تسلّم شريحة مرئية من طرف إلى طرف (بيانات
   ← API ← شاشة ← اختبارات ← نشر) قابلة للعرض فوراً.
3. **سلطة تنفيذ كاملة — محلياً** — الفروع والتنفيذ والبوابات والدمج
   بيد الوكيل بشفافية (ملاحظة السلطة + سجل العمل + تحديث سجل الرحلات)،
   والدمج يقع **محلياً** (main خطي). أما الدفع إلى الأصل — وهو نفسه
   زناد نشر الإنتاج (نشر تلقائي من `main`) — فبكلمة المالك الصريحة
   فقط، وطلبها في كل ختام. البوابات (قاعدة 4) وسجل مدخلات المالك
   (الميثاق §7) يبقيان المقيّدين الوحيدين.
4. **البوابات مقدسة** — لا تجاوز ولا إضعاف: eslint ← build ←
   `tsc --noEmit` (بعد typegen) ← vitest ← playwright. الشريحة «انتهت»
   والكل أخضر، وe2e هو تعريف الإنجاز الآلي.
5. **القياس يحكم** — العقود تُقاس حية قبل البرمجة؛ كل تعديل يُتحقق منه
   حياً عبر حلقة next-dev-loop (`/_next/mcp` + `agent-browser` على خادم
   dev القائم)؛ النشر يُثبت بظهور المسار أو commitHash، أبداً ببصمات
   chunks؛ كل رقم يحمل تاريخه. وإن تعذّر التحقق الحي (باك اند متوقف
   مثلاً) **فتوقف عن الادعاء وصرّح بذلك** بدل التخمين — وحقائق التطبيق
   المقيسة فوق رأيك فيما هو صحيح.

## 4. دورة الشريحة (شريحة = فرع = دمج محلي؛ الـ PR يولد لحظة الدفع)

1. مزامنة (الطقس أعلاه) ← 2. قراءة السجل ← 3. **قياس العقد حياً**
   (staging أولاً؛ الأشكال الفاشلة كما الناجحة) ← 4. فرع `feat/*` أو
   `docs/*` ← 5. تنفيذ بأنماط البيت (§5) مُسنداً إلى الوثائق المحزومة +
   **إدخال الملاحة** — سطح لا يُصل إليه ليس شريحة — **مع تحقق حي بعد
   كل تعديل** (حلقة next-dev-loop: الخادم من `.next/dev/lock` ثم
   المنظوران `/_next/mcp` و`agent-browser`) ← 6. اختبارات ثلاثية: وحدة
   (ربط a11y) + e2e محكم بلا بيانات + e2e حي اختياري لعقد كامل (نمط
   `REGISTER_LIVE=1` — يُنفَّذ يدوياً قبل الدمج) ← 7. البوابات بترتيبها
   ← 8. **دمج محلي** (`git merge --ff-only` إلى main — الأصل والإنتاج
   لم يُلمسا) ← 9. **تحديث سجل الرحلات** (قاعدة الميثاق §9 — دمج محلي
   أيضاً) ← 10. worklog + ختام عربي تفاعلي (≤100 كلمة + الخطوة التالية
   + **طلب كلمة الدفع**) ← 11. **انتظار**: لا شيء يتحرك على الأصل حتى
   كلمة المالك الصريحة («ادفع») — الدفع هو زناد نشر الإنتاج ← 12.
   **بالكلمة فقط**: دفع الفرع ← PR (عنوان إنجليزي conventional + متن
   عربي مقيس + جدول بوابات + ملاحظة السلطة + سجل الكلمة) ← دمج squash
   (هنا يولد `(#N)`؛ الاندماج المحلي المؤقت يُستبدل بتاريخ GitHub
   الكنسي — reset لـ main على origin، نفس الشجرة) ← حذف الفرع ←
   **إثبات الإنتاج**: مسار جديد ← استطلاع ظهوره (~2 دقيقة مقيساً)؛
   إصلاح خادمي فقط ← commitHash من Railway GraphQL (curl بمتصفح UA؛
   python محجوب 1010). شرائح مدمجة محلياً عدة قد تركب كلمةً واحدة
   كموجة PRs متتابعة — قرار المالك لحظتها.

**الحلقة الحية (تفصيل الخطوة 5)**: تُتَّبع
`.agents/skills/next-dev-loop/SKILL.md` حرفياً بدءاً من الـ preflight:
خادم واحد يُوجد عبر `.next/dev/lock` (حي ← اتصل ولا تبدأ مكرراً؛ ميت
والخادم لازم ← ابدأه أنت؛ لا حذف `.next` والخادم يعمل)؛ منظوران
يتقاطعان — `/_next/mcp` (منظور الإطار: المسارات وأخطاء الترجمة
والأخطاء والسجلات؛ ردوده SSE فاقرأ JSON من سطر `data:`) و
`agent-browser` (منظور المتصفح: DOM والكونسول والشبكة وشجرة React بـ
`--enable react-devtools`) — وعند اختلافهما اشك في العدة (جلسة متصفح
بالية) قبل التطبيق؛ وأربعة فحوص لكل تعديل: يترجم، ويعمل بلا أخطاء،
ويتصرف كما قُصد، وسلوك React سليم. وإن تعذّر التحقق الحي فتوقف عن
الادعاء وصرّح — «غير متحقق» معلنةً خير من تخمين.

## 5. أنماط البيت (ما «الصحيح» هنا)

- **قنوات البيان**: `backendGet` / `backendSend` (بجلسة، RSC +
  Server Actions) و `backendSendPublic` (الكتابة العامة باختيار الجلسة —
  نموذجا L34 والتسجيل العام) من `src/lib/api/server.ts`. لا self-fetch
  عبر `/api/backend`.
- **الفشل الأمين**: الأعطال المتوقعة تعود بياناتٍ لا انهيار عرض.
  `problemMessage()` يظهر problem+json الخلفي حرفياً (`userMessage` ←
  `detail` ← `title` ← بديل عربي). الكلمات العربية المؤلَّفة محلياً فقط
  حيث رسالة الخلفي **مقيسة الخطأ** لحالتها (دَين 409 التسجيل مثالاً)
  ويُسجَّل الدَّين في الميثاق §5.
- **النماذج**: `useActionState` + مكوّن `Field` (ربط aria آلي) +
  `ActionState` بحقل `field?` اختياري. تحقق HTML يطابق حدود bean
  الخلفي حرفياً (كما قِيست من OpenAPI + probing الحي).
- **الأسطح**: العامة للزوار ومحركات البحث؛ الخاصة بجلسة تحمل
  `noindex`. نصوص عربية RTL؛ `dir="ltr"` للبريد/الهاتف/التاريخ.
- **التحقق الحي**: بعد كل تعديل جولة next-dev-loop كاملة (اتصال بخادم
  dev القائم عبر `.next/dev/lock`، المنظوران يتقاطعان) — والتعديل يُقاس
  بسلامة نظام BFF كله (مصادقة + بروكسي + جلسة) لا بالملف الملموس
  وحده؛ لا ترقيع يترك ديناً.
- **الاختبارات**: vitest يعرض النماذج بـ `renderToStaticMarkup` مع
  `useActionState` مُحاكى (النموذج المرجعي:
  `tests/unit/register-form.test.ts`)؛ e2e الدخاني محكم بلا صفوف
  بيانات؛ الجولات الحية بعلم بيئة اختياري.
