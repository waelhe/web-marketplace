## 0. القاعدة الحاكمة — «الباك اند يتبع الواجهة»

كل شريحة أدناه معرّفة بـ**السطح الذي تفتحه في الواجهة المبنية فعلًا**، لا
بعقد مقترح في الفراغ. مبدأ الاستبدال المكاني: عند هبوط العقد، تحل
القراءة الحقيقية محل طبقة العرض **في نفس سطح المنتج بصفر تغييرات
واجهة** (سابقة N8 للسوق: `neighborhood-design.ts` → عقد L50 بنفس الصفحة).
كل طبقة عرض تحمل `demo-` في معرفاتها و«بيانات عرض» في شاراتها —
**مفتاح الرصد: ابحث عن الشارة، تجد العقد المطلوب**.

## 1. خريطة الأسطح: الحقيقي مقابل المُعلَّق (قياس 2026-10-04)

| السطح (مبني) | قناته اليوم | العقد البديل |
|---|---|---|
| بطاقة السياق — «ما حول العقار» (listings/[id]) | **قراءة نطاقية حقيقية** (`/search?lat&lng&radiusKm` بنجوم W3) | **K1** — قراءة مجمعة واحدة |
| بطاقة السياق — مؤسسات/نبض/رؤى/تقدير | طبقة عرض مُوسومة بتواريخ حساب | **K1/E1/E2** |
| حاسبة الأقساط (listings/[id]) | **رياضيات أمامية نقية** (مختبرة وحدة) | لا شيء — مكتملة |
| المتجر: تصفّح/منتج/سلة/إتمام/طلبات | سلة **كوكيز رسمية** + عالم منتجات عرض | **M1→M3** (الأعظم قيمة) |
| نسيج المؤسسات: سكة الأقسام + الجامعات + لوحة القسم | عرض مُوسوم (بوابة العضوية الحية نطاق اليوم) | **G2/G3** |
| شارة مقيم/مغترب | عرض مُوسوم (المعادلة `{الشارة} في {الحي}` جاهزة) | **G1** |
| طريقتا الحجز (فوري/طلب عرض) | **قناة leads الحقيقية موسومة كوضع ثانٍ** | **T1** (تجميع العرض في عقد واحد) |
| حزم الجلسات + توثيق الخلفية | عرض مُوسوم | **T2/T3** |
| بطاقة الجار (أربعة طوابق) | طوابق الهوية/الحضور/الخصوصية **حقيقية** + خلايا سمعة مقيسة | **P1** (الخلايا المتبقية) |
| بابا الرسم البياني والربح (الأدمن) | geo **مُخدَم** (بوابة الفهرس) + مدفوعات **حقيقية** + بوابات صريحة | **G4/A1/R1** |
| «بضمان المنصة» في الحجز | زر صادق معطّل بنص البوابة | **R1** (بوابة النسبة) |

## 2. الشرائح بترتيب الأولوية (L-series)

> الترقيم يكمل سلم الباك اند الحي (L52 آخر ما هبط؛ V105 آخر ترحيلة).

### L53 — معيار الجلسة (الموجة S، أولًا — قرار مالك بوابةً)
**يفتح:** مدير الجلسات في الطابق الرابع من بطاقة الجار + أساس الجوال.
**القرار المعلَّق (حكم PR #498):** (أ) عميل سري للتطبيق الموثوق (نمط bff —
التجديد يعمل له حرفيًا) أو (ب) إعادة مصادقة دورية RFC 9700. المسار الثالث
مرفوض من مصدر الإطار (SAS 7.1.1: `OAuth2RefreshTokenGenerator` → null
للعميل العام؛ `PublicClientAuthenticationConverter` يقبل PKCE للكود فقط).
**العقد (المسار أ):** نافذة منزلقة 90 يومًا على RT عميل bff (`reuseRefreshTokens(true)` +
TTL منزلق)؛ **(ب):** إبقاء 900 ثانية + توثيق جولة الإذن الجديد في
`docs/mobile-app-integration.md`.
**S2 (الويب):** نفس النافذة المنزلقة لـ`marketplace-bff` — القيد المقاس
(Set-Cookie يسقط في RSC) يُحل داخل أنماط الإطار الرسمية (route handler /
server action فقط للكتابة).
**S3:** `GET /me/sessions` + `DELETE /me/sessions/{id}` + خروج عالمي.
**DoD:** قياس حي (RT القديم ميت بكلمات `invalid_grant` + النافذة تُعاد) + جولة
إبطال جهاز (401/302 للملغى) + الوثيقة محيّنة.

### L54–L56 — إغلاق نواة الحي (الموجات C — صغيرة سريعة)
**يفتح:** القائمة المحادثات (C1: `GET /messages/conversations` بمعاينة
آخر رسالة وعدّاد غير مقروء — الإناء المقسّى نفسه)؛ الملف العام للجار
(C2: `GET /users/{id}` بمجموعة عامة فقط: اسم، شارات، حي، انضمام، ملخص
سمعة — **فجوة #12 المسجلة، بطاقة الجار تستهلكها مباشرة**)؛ توصيات الأعمال
(C3: كتابة نصية بلا حجز مسبق على صفحة العمل)؛ المفقودات المهيكلة وتنبيهات
النطاق (C4)؛ النطاق المجاور + WS + شارة النشاط (C5).
**DoD لكل:** جولة API مقيسة بكلمات الفشل الأصلية + واجهة تستهلك العقد
بنفس السطح (بلا تغيير سطح).

### L57–L59 — نسيج المؤسسات (الموجات G)
**يفتح:** سكة الأقسام ولوحة القسم والجامعات — كلها **مبنية وتنتظر العقود**.
**العقد:** `Institution` (kind: UNIVERSITY/COLLEGE/SCHOOL/INSTITUTE/MOSQUE)
على شجرة geo؛ مجتمع الكلية = **تعميم وحدة neighborhood** (نفس `scope_type`
وأبواب L41–L52 — لا وحدة ثانية)؛ الأقسام الخاصة: قائمة أعضاء + لوحة
`noindex` + دور مشرف قسم؛ نوع العضوية `RESIDENT/EXPAT` (ترحيلة عمود واحد
على membership + الشارة في الصدى).
**DoD:** عضوية مغترب تقيس حضورًا كاملًا من الخارج؛ 403 مقيسة لغير عضو
القسم (البوابة نفسها التي تعرضها الواجهة اليوم بنطاق الحي)؛ الجامعة
+كليات مبذورة تعمل ببوابات اللوحة نفسها.

### L60–L65 — المتجر (الموجات M — العمود الأعظم)
**يفتح:** المتجر كله (تصفّح/منتج/سلة/إتمام/طلبات مبني بالكامل على
display؛ السلة كوكيز رسمية تحل محلها الجلسة المُسنَدة).
**العقد بالترتيب:** M1 قاموس فئات المتجر (بوابة مالك — عنصر سجل §7/9)
+ `Product`/variant/وسائط عبر القناة الموقعة الموجودة؛ M2 واجهة المتجر
+ صفحة المنتج بأسئلة وأجوبة + ملخص تقييم البائع (نمط صفحة المزوّد العامة
L36 حرفيًا)؛ M3 سلة متعددة البائعين → **Order لكل بائع** بحالات
PREPARING/SHIPPED/DELIVERED/RECEIVED (نفس مفردات الحالة التي تعرضها
الواجهة اليوم — احترم الربط الأمامي)؛ M4 تنفيذ + نزاعات (تعميم نزاعات
الحجز) + دفتر بائع (نمط L-series)؛ M5 تقييم البائع بعد RECEIVED فقط؛ M6
منتجات «من المنصة» في نفس السلة.
**DoD:** دورة طلب كاملة مقيسة (سلة متعددة بائعين → طلبان مستقلان →
حالات بتقدم الأطراف الصحيحة فقط بـ403 مقيسة) + استبدال طبقة العرض في
نفس الأسطح بصفر تغيير واجهة.

### L66–L70 — طبقة Redfin والسياق (الموجات E/K)
**يفتح:** بطاقة السياق (المبنية) تتحول من تركيب إلى **قراءة واحدة**.
**العقد:** E1 مجاميع الحي (نطاقات أسعار، أيام في السوق، نشاط — مؤرَّخة،
مُوادّة materialized)؛ E2 التقدير (نموذج من صفقات المنصة نفسها + مدى ثقة
+ ملاحظة منهج — الإطار «تقدير» معروض جاهز)؛ **K1 القراءة المجمعة
`GET /properties/{id}/context`** (أعمال قرب + نبض + سلامة + مؤسسات +
اتجاه — تدهور صادق لكل كتلة)؛ E4 فعاليات الدار المفتوحة (عيار عقاري على
L49)؛ E5 مكتمل (الفلاتر أمامية على معايير search القائمة + الحاسبة).
**DoD:** البطاقة تستهلك عقدًا واحدًا (صفر تركيب أمامي — قاعدة «قراءة
واحدة للسطح») + كل كتلة صادقة الفراغ.

### L71–L74 — الخدمات والدليل (الموجات T/D)
**يفتح:** الحزم وشارات الخلفية وأرضيات صفحة العمل ولوحة صاحب العمل.
**العقد:** T1 تجميع «طلب عرض» في عقد leads موسوس (الوضعان صريحان في
البطاقة جاهزان)؛ T2 `ServicePackage` (جلسات N + تقدم + مادة)؛ T3 شارة
توثيق الخلفية (دورة V78 بمستند مغاير)؛ T4 قاموس تصنيف التدريس (نمط
السجل الحي S2)؛ D1 أرضيات صفحة العمل (ساعات+مفتوح-الآن **مخدَم W2** +
قائمة أسعار + أسئلة)؛ D2 لوحة أداء صاحب العمل (وصول/تفاعل/حملة W5)؛ D3
مسار المطالبة بعمل (دورة التوثيق معادة).
**DoD:** حزمة تُشترى وتتقدم بجلسة لكل قيد؛ «مفتوح الآن» يقيس ضد نافذة
معروفة؛ لوحة صاحب العمل تقرأ عمله وحده (403 مقيسة).

### L75+ — الربح (الموجات R — بوابة مالك على النسبة)
**يفتح:** زر «بضمان المنصة» (معطَّل صادقًا اليوم بنص البوابة نفسه) +
بوابة الربح الكاملة.
**العقد:** R1 `EscrowEngagement` على حجز/طلب/خدمة (HELD→RELEASED/REFUNDED
بمهلة وقرار نزاع) + **نسبة → قيود دفتر غير قابلة للتعديل** (نمط
AD_DEBIT W5)؛ R2 مخزون مواضع الإعلانات + استهداف حارة/اهتمام؛ R3 بيع
المنصة المباشر (تثمين مدفوع/ترقية/توثيق معجّل)؛ R4 طبقة حلول الأعمال.
**DoD:** جولة ضمان كاملة مقيسة (طلب→حجز→استلام→إفراج→قيد النسبة) + كل
رقم في بوابة الربح يتتبع لقيد دفتر (قاعدة «لا رقم بلا قيد» — معروضة
في البوابة المبنية).

## 3. الأنضباط القائمة (غير قابلة للتفاوض)

1. **المصدر الرسمي للإطار أولًا** — قاعدة المالك المسجلة: كل قرار تصميم
   يُقاس ضد مصادر Spring Authorization Server/Boot 4.1.1 المطابقة للإصدار
   (سابقة الحكم #498: مولّد التوكنات ومحوّل المصادقة قرآء من المصدر) — لا
   سلك مخصص يحارب الإطار.
2. **Modulith**: كل عقد جديد داخل وحدة قائمة أو وحدة معرّفة بحدود صريحة
   (`@ApplicationModule`)، والمنافذ محايدة الإطار (سابقة
   `sharedPortsAreFrameworkNeutral`).
3. **Flyway**: ترحيلات متسلسلة مع منع التصادم مع الفروع المفتوحة (سابقة
   V88/V89 محجوزتان) + مرايا Envers بعرف V24/V83/V91.
4. **RFC 7807 + traceId** لكل فشل جديد بكلمات عربية أصلية من الخلفي
   (الواجهة تعرضها حرفيًا — `problemMessage`).
5. **الإقلاع-converge** للإعدادات (نمط on-boot) بلا يد SQL.
6. **البوابات الستة** (CI + Integration + CodeQL ×2 + Container + Trivy)
   خضراء قبل أي دمج + دورة CodeRabbit مغلقة — البروتوكول نفسه.
